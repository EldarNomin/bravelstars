# План разработки

Рабочее название — **Bravel Stars**. Мобильный арена-шутер 3v3 на Godot 4.7, сначала Android. Дизайн — `docs/DESIGN.md`, задачи — `docs/TASKS.md`, процесс студии — `docs/studio/PROCESS.md`.

> **IP.** Механики жанра брать можно. Нельзя: имена, внешность героев, арт, звуки, логотипы и названия режимов Supercell. Название для магазина приложений — своё, не созвучное «Brawl Stars».

## Принцип: сначала вертикальный срез, потом всё остальное

Мы не строим сеть, аккаунты и магазин, пока не доказано, что **матч с ботами интересен**. Каждая веха заканчивается гейтом «идём дальше / дорабатываем». При «нет» — замораживаем новые фичи и 2 недели тюним.

| Веха | Что внутри | Гейт: идём дальше, если… | Ориентир |
|---|---|---|---|
| **VS0 «На телефоне»** | APK из CI, джойстики, 3 героя, 1 карта, боты v1, матч до 10 убийств | ставится на телефон, ≥ 30 FPS на недорогом Android, управление не раздражает | ~3–4 недели |
| **VS1 «Интересно с ботами?»** | режим «Добыча», game feel (VFX, хитстоп), меню из 2 экранов, плейтест-протокол | владелец + 2–3 знакомых после 5 матчей хотят ещё; 8/10 поняли кусты без объяснений | +4–5 недель |
| **VS2 «Сеть»** | сервер на VPS, 2+ телефона в матче по коду комнаты, предсказание движения | играбельно при 150 мс пинга и 5% потерь (стенд N-05) | +6–8 недель |
| **VS3 «Закрытый тест»** | 6 игроков, простой подбор матча, крэш-репорты, подписанная сборка, второй режим | матч на 6 человек без рассинхронов и падений | +4 недели |
| **M4 «Мета»** | Nakama, прогресс, косметика, 10 героев, стор | только если VS0–VS3 пройдены | дальше |

Сроки — для владельца, который работает над игрой по вечерам: скорость упирается в ревью, мерж и тесты на телефоне, а не в агентов. Решения по гейтам записываются внизу этого файла.

## Ключевые технические решения

| Решение | Выбор | Почему |
|---|---|---|
| Движок | Godot 4.7.2 (`.godot-version`) | бесплатно, простой экспорт на Android, headless-сервер |
| Язык | GDScript со статической типизацией | агенты пишут на нём уверенно |
| Графика | 3D low-poly, фиксированная камера сверху под углом, рендерер Mobile | как в жанре; заглушки до VS1 |
| Архитектура | симуляция (`src/sim`) отделена от отображения, тики 30 Гц, команды ввода | сервер запускает ту же симуляцию |
| Сеть | авторитарный сервер, ENet; клиент предсказывает своё движение и **исправляется по снимку сервера** | хэш-сверка клиента с сервером невозможна: float на ARM и x86 расходится |
| Бэкенд | до VS3 — свой сервер на VPS и вход по коду комнаты; Nakama — только в M4 | не строим мету до доказанного «фана» |
| Тесты | GUT + gdlint в GitHub Actions | |

## Главные риски

1. **Узкое место — владелец** (мерж и тест на телефоне). → Пакетный мерж по метке `ready-to-merge`, не больше 5 открытых PR, автомерж PR только с данными.
2. **Игра не интересна, а сделано много.** → Гейт VS1 до сети и меты.
3. **Получается клон без своего лица.** → Столпы в `DESIGN.md`; каждое решение проверяем против них.
4. **Сетевой код ломает ядро.** → Детерминированность и тесты уже есть; полная сериализация и откат (N-00) и стенд с задержками (N-05) — до предсказания (N-03).
5. **Публикация в Google Play из России:** оплата аккаунта разработчика, требование закрытого теста (12 тестировщиков на 14 дней для новых личных аккаунтов), санкционные ограничения. → Решить, на кого оформлять аккаунт, до VS3; запасной вариант — RuStore.
6. **Производительность на слабых телефонах.** → Замер FPS с VS0 (C-12), а не в конце.

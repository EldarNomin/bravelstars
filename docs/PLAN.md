# План разработки: мобильный арена-шутер 3v3 (Godot, Android)

Рабочее название — **Bravel Stars**. Жанр — top-down арена-шутер с короткими матчами (2–3 мин), как Brawl Stars.

> **Важно про IP.** Механики жанра (джойстики, кусты, супер-удар, режимы) копировать можно. Нельзя: имена и внешность героев Supercell, их арт, звуки, логотипы, названия режимов («Gem Grab», «Showdown»). Всё своё. Перед публикацией в Google Play название тоже должно быть своим, не созвучным «Brawl Stars».

## Ключевые решения

| Решение | Выбор | Почему |
|---|---|---|
| Движок | Godot 4.x, последняя стабильная (версия фиксируется в `.godot-version` в задаче F-02) | бесплатно, лёгкий экспорт на Android, хороший headless-сервер |
| Язык | GDScript со статической типизацией | агенты пишут на нём уверенно, нет проблем с C# на Android |
| Графика | 3D low-poly, фиксированная изометрическая камера, рендерер **Mobile** | как в жанре; на старте — примитивы-заглушки |
| Архитектура | **Симуляция отделена от отображения** с первого дня: вся логика — в `src/sim`, работает по тикам 30 Гц от «команд ввода». Отображение (`src/view`) только читает состояние | позволит в фазе 3 перенести симуляцию на сервер без переписывания |
| Мультиплеер | Авторитарный сервер (headless Godot), ENet/UDP, предсказание своего движения + интерполяция чужих | честность и защита от читов |
| Бэкенд | Nakama (open source, есть Godot SDK): аккаунты, матчмейкинг, хранилище | не пишем свой бэкенд |
| Хостинг | свой VPS, Docker | уже есть |
| Тесты | GUT + gdlint (gdtoolkit) в GitHub Actions | |

## Фазы и вехи

| Фаза | Срок (ориентир) | Веха — что можно показать |
|---|---|---|
| 0. Фундамент | неделя 1 | Пустой проект собирается в APK в CI |
| 1. Ядро геймплея | недели 2–4 | **M1:** на телефоне бегаю героем, стреляю, прячусь в кустах, убиваю ботов на одной карте |
| 2. Режимы и боты | недели 5–6 | **M2:** полный оффлайн-матч 3v3 с ботами, меню, 6 героев, 2 режима |
| 3. Мультиплеер | недели 7–11 | **M3:** 6 человек на реальных телефонах в одном матче через сервер на VPS |
| 4. Мета и релиз | недели 12–16 | **M4:** закрытый тест в Google Play: прогресс, трофеи, магазин без реальных платежей |

Сроки — ориентир при параллельной работе 4 агентов; реальный темп упирается в ревью и тесты на телефоне.

Владение папками (чтобы не было конфликтов при слиянии) — в `AGENTS.md`. Список задач — в `docs/TASKS.md`.

## Главные риски

1. **Сетевой код** — самое сложное. Снижаем: симуляция детерминированная и отделена от отображения с фазы 1; тестовый стенд с задержкой/потерями пакетов (N-05) до игры на людях.
2. **Производительность на слабых Android** — профилировать на реальном недорогом телефоне с M1, а не в конце.
3. **Расползание стиля кода между 4 агентами** — общие правила в `AGENTS.md`, gdlint в CI, все PR через ревью Claude.
4. **Арт** — заглушки до фазы 4; финальный стиль фиксируется в style guide (F-05) рано, чтобы контент не переделывать.

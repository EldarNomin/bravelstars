# Bravel Stars · Unity

Android-проект на **Unity 6000.3.25f1 (6.3 LTS)**. Откройте в Unity Hub именно эту
папку, затем `Assets/Scenes/Bravel.unity` и Play. Если сцена ещё не создана,
выполните `Bravel → Configure mobile project`.

Лобби → выбор героя, карты, режима и сложности → матч 3v3 с ботами → результат → лобби.
Перенесены Рысь, Наковальня, Шишка, четыре игровые карты, «Бой команд» и «Добыча»,
боевые числа из Godot, модели и пять анимаций каждого героя. Исходный Godot-проект
сохранён уровнем выше как reference для проверки переноса.

## Мобильное управление

- Левый стик: движение. Правый: удерживать и тянуть для прицеливания, отпустить
  для выстрела; тап даёт автоприцел. Золотой стик: аналогичное управление супером.
- Каждый стик держит собственный pointer ID. Пауза, потеря фокуса, сворачивание
  и изменение safe area сбрасывают удержания. После возврата игра остаётся на паузе.
- Ландшафтная ориентация в обе стороны; UI внутри `Screen.safeArea`.
- На ПК: WASD, пробел для автоприцельной стрельбы, Q для супера, Escape для паузы;
  мышью также работают экранные стики.

## Что настроено для Android

IL2CPP, ARM64, минимум Android 8/API 26, target API 36, OpenGL ES 3, optimized frame
pacing. Сборка — локальный debug APK с отдельным ID `com.bravel.arena.unity`.
Ключ публикации не нужен. Режимы качества: 30 FPS/1600 пикселей по длинной стороне
и 60 FPS/1920 пикселей. Фактический FPS зависит от устройства.

Симуляция идёт на 30 Гц независимо от рендера. Представление интерполирует позиции,
геометрия арены объединяется static batching, снаряды используют ограниченный пул.
Нет теней в реальном времени, постобработки, сторонних рекламных/аналитических SDK.
Номер героя, чувствительность и выбранное качество сохраняются локально.

## Воспроизводимые проверки

Из корня репозитория:

```powershell
python tools/unity/export_data.py --check
dotnet run --project tools/unity/checks/Checks.csproj --configuration Release
powershell -ExecutionPolicy Bypass -File tools/unity/verify.ps1 -WithAndroid
```

Последняя команда требует активированной лицензии Unity и Android Build Support
с SDK/NDK/OpenJDK. Она создаёт Windows player для автоматического прогона, проверяет
интерфейс в 16:9, 20:9 и 4:3, затем собирает Android APK. Логи и скриншоты —
`artifacts/unity/`; APK — `unity/Builds/Android/bravelstars-unity-debug.apk`.

Меню редактора: `Bravel → Validate simulation and assets`, `Build Android APK
(development)`, `Build Windows smoke player`. На GitHub проверяется переносимость
ядра C# и соответствие данных исходнику; это не Unity/Android CI.

Данные регенерируются `python tools/unity/export_data.py`. Модели:

```powershell
blender -b --python-exit-code 1 -P tools/unity/export_models.py
```

Скрипт берёт собственные GLB из `assets/models`, сохраняет FBX и журнал с SHA256,
геометрией и анимациями. Unity импортирует FBX штатно, без glTF-плагина.

## Границы проверки

Отдельные результаты — в `../docs/unity/VALIDATION.md`. Тесты pointer ID на ПК
проверяют обработчики ввода, но не доказывают удобство физического мультитача.
Приёмка VS0 требует установки APK на недорогой Android, проверки управления,
≥30 FPS, нагрева и памяти после нескольких полных матчей. Подключённого телефона
на момент начала переноса не было.

Симуляция остаётся отделённой от Unity. Это локальная игра с ботами: сетевой
транспорт, аккаунты и магазин в исходной версии ещё не реализованы. Старые Godot
сохранения не читаются: локальные настройки Unity имеют отдельные ключи.
Числа героев сохранены; алгоритм RNG и поиск пути переписаны на C#, поэтому
результаты матчей не обязаны побайтно совпадать с Godot или между ARM/x86.
